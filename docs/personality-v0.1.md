# 人物选择画像与证据规范 v0.1

> v0.6 的可执行聚合、子维度、情境统计和事件覆盖见 [personality-v0.6.md](personality-v0.6.md)。本文保留原始证据边界；下方关于 prototype 尚未实现的说明不代表当前 `game/portrait.py` 的运行状态。

> **实现状态**：第 1–10 节定义后续画像系统的完整目标，示例结构不等于当前引擎已经实现的接口。当前规则原型只保存有限的情境行为记录，不实现完整证据聚合或人格分析；它与目标规范的字段适配和限制见第 11 节。

## 1. 本版本的目标

从玩家已经完成的选择中，生成有事实依据、能够呈现变化与矛盾的人物画像，并为人生结束时的人物志提供材料。

本版本的八个维度是**尚未经过心理测量验证的游戏设计假设**。它们描述“这位角色在本局、这些条件下怎样行动”，不输出玩家真实人格、临床结论、心理测量分数、百分位或置信概率。维度更多不等于测量更准确。

首版的输出单位是：**按情境整理的行为次数、对应机会次数和可回看的证据条目**。大模型可以组织语言，不能增加不存在的经历，不能根据文风、性别、身份或单次结果补充心理结论。

维度的机器可读定义见 `content/personality-dimensions.json`。

## 2. 与角色数值系统分离

| 数据层 | 例子 | 如何使用 | 不应如何使用 |
| --- | --- | --- | --- |
| 需求与即时状态 | 健康、精力、压力、归属感 | 形成代价、需求和情境 | 不把压力高直接解释成某种人格 |
| 可支配资源与条件 | 金钱、时间、物资、住所、资格 | 校验选项是否可执行 | 不把付不起钱解释为不愿帮助 |
| 能力 | 体能、职业技能、知识、沟通技能 | 决定执行门槛和结果概率 | 不把不会做解释为不想做 |
| 价值优先级 | 家庭、安全、自主、成就、公平 | 描述一次取舍维护了什么目标 | 不把目标直接等同于人格特质 |
| 关系状态 | 对具体 NPC 的信任、亲密、承诺、冲突 | 判断双方可做什么，以及行为指向谁 | 不用一个“人缘值”替代所有关系 |
| 选择证据 | 面临哪些可行方案，最终选了什么 | 形成角色画像 | 不作为可消耗资源或行动硬性门槛 |

例如，“沟通能力高”“喜欢主动交往”“愿意向人求助”是三个不同事实。可以关联，但不能共用同一个数值。

**不因推断出的性格锁定选择。** “勇气不足不能求救”“善良不足不能捐款”会先规定角色，再把受限行动当作性格证明，形成循环。可因现实条件、能力或身份锁定选项，并明确记录原因。

## 3. 八个工作维度

| ID | 工作维度 | 主要观察 | 关键区分 |
| --- | --- | --- | --- |
| `exploration` | 探索与熟悉偏好 | 是否接触新信息、尝试陌生事物、先调查再尝试 | 不等于聪明、创新能力或愿意冒生命危险 |
| `persistence` | 目标坚持与调整 | 在可继续的情况下坚持、调整办法、暂停或放弃 | 调整目标不自动等于缺乏毅力；沉没成本不是优点 |
| `social_initiative` | 社交发起方式 | 主动接触、等待回应、选择独处 | 不等于沟通能力、受欢迎程度或社交关系数量 |
| `care` | 关怀行为与对象范围 | 如何注意需求、提供支持，以及优先帮助谁 | 不把贫困导致的无力帮助记为冷漠 |
| `fairness` | 公平与承诺取舍 | 如何分配利益、兑现约定、披露利益冲突 | 合法、平均、守约和公平并非总是一回事 |
| `conflict_style` | 冲突处理方式 | 协商、坚持立场、妥协、离开、回避、寻求第三方 | 多种策略，不合成“好脾气到坏脾气”的单轴 |
| `risk_taking` | 风险应对方式 | 接受、拒绝、降低、调查或转移风险 | 区分可知风险、损失承受能力和被迫冒险 |
| `help_seeking` | 求助与自主应对 | 求助、接受帮助、先独立尝试、拒绝或延后求助 | 区分独立偏好与没有可信、可用的求助渠道 |

每个维度可包含多种行为，标签本身没有正负分。`positive_examples` 表示“足以支持观察的例子”，不表示道德上更好；`counter_examples` 表示“会推翻简单归因的例子”，不表示负面人格。

价值取向暂作为事件的目标标签单独记录。例如，“牺牲升职机会照顾父亲”涉及家庭责任与成就的取舍；只有结合可行替代方案和实际负担，才能进一步描述其关怀模式。不要把一个行动同时当作八个维度的证据。

## 4. 什么才算一次有效观察机会

一次决策只有同时满足以下条件，才进入该维度的行为聚合：

1. 相关情境已经实际展示给玩家，而非仅存在于事件库。
2. 在玩家作决定的时刻，至少有两个与该维度相关、含义不同且真正可执行的方案。
3. 玩家获得了足以区分这些方案的关键信息；隐藏的后果不用于倒推当时动机。
4. 维度相关的选择差异没有完全被硬性约束决定。
5. 事件作者事先标记了观察维度、行为分类和失效条件，而非结局生成时临时解释。

这些规则按维度判断：同一个选项可能为“冲突处理”提供观察，却不足以判断“关怀”。只剩一个可行选项时可以记录事实与生存处境，不能形成自由偏好的证据。

锁定的选项保存在记录中，但**不算拒绝、不进入对应选择机会的分母**。未触发的事件也不是拒绝。自动结算、默认超时、误操作撤销和开发调试操作不作为自愿选择证据。

## 5. 证据记录格式

下面是概念结构。字段可以由规则引擎、事件元数据和当时状态快照共同填充；不能仅依赖生成文本解析。

```json
{
  "evidence_id": "ev_run01_decision0042_care",
  "run_id": "run01",
  "actor_id": "player_character",
  "decision_id": "decision0042",
  "event_instance_id": "neighbor_illness_004",
  "event_template_id": "neighbor_illness",
  "event_template_version": "0.1.0",
  "life_stage": "young_adult",
  "age_years": 23,
  "dimension_id": "care",
  "behavior": "provide_practical_support",
  "context_tags": ["target:neighbor", "pressure:low", "visibility:private"],
  "opportunity": {
    "status": "eligible",
    "presented_options": ["spend_time", "pay_transport", "decline"],
    "feasible_relevant_options": ["spend_time", "decline"],
    "locked_options": [{"option_id": "pay_transport", "reason": "insufficient_money"}],
    "selected_option": "spend_time",
    "known_information": ["邻居需要有人陪同就医", "陪同预计占用半天"],
    "exclusion_reasons": []
  },
  "burden": {
    "resource_costs": [{"resource": "free_time_hours", "cost": 4, "available_before": 8, "share": 0.5}],
    "essential_needs_threatened": false,
    "category": "material"
  },
  "constraint_tags": ["cash_shortage"],
  "evidence_strength": "direct_contextual",
  "value_targets": ["support_neighbor"],
  "related_npc_ids": ["npc_neighbor_02"],
  "facts": ["角色选择用四小时陪同邻居就医"],
  "alternative_explanations": ["双方可能存在尚未表达的互惠期待"]
}
```

`opportunity.status` 使用 `eligible`、`constrained`、`ambiguous`、`not_voluntary`。只有 `eligible` 进入自由选择行为计数；其他状态保留为事实、局限或待审核条目。

`evidence_strength` 只用描述性类别：

- `direct_contextual`：有可行的相关替代方案，行动含义明确；只支持当下情境的行为描述。
- `mixed_motive`：仍有真实选择，但多种动机无法区分；单独展示，不合入较明确的行为计数。
- `insufficient`：缺少机会、信息或元数据；保留事实，不作性格归因。

这些标签不是置信概率，也不支持把“直接证据”转换为某个百分比。

### 5.1 情境与负担

最低限度保留人生阶段、关系对象、资源压力、公开/私下情境和关键信息。风险事件另保留角色当时可知的风险信息、潜在损失和可承受程度。

成本既记录绝对量，也记录占当时可支配资源的比例；分母为零或资源不可比较时记 `null`。不要把十元对穷人和富人的代价当作相同，也不要把金钱、受伤风险和关系损失强行换算成一个总负担值。

负担类别可以由事件和规则共同标记为 `negligible`、`material`、`essential_need_threat` 或 `unknown`；类别用于分组，须保留计算依据。面临基本生存威胁时，对稳定偏好的解释尤其有限。

### 5.2 反例与替代解释

同一角色对家人慷慨、对陌生人谨慎，可以同时成立。既保留支持某种模式的事件，也保留不同选择；不能让总结器挑选几个“符合人设”的故事。

区别两类记录：

- **行为反例**：在相近情境下实际作出了不同选择。例如两次有余力的求助中，一次帮助、一次拒绝。
- **归因限制**：行为发生了，但存在足以解释它的条件。例如拒绝求助是因为唯一求助者曾经伤害角色。

反例不自动抵消前面的事实；归因限制也不是人格的相反证据。

## 6. 首版聚合算法：计数、分组、引用

1. 从已提交的决策日志读取记录，不从人物志反向提取证据。使用 `run_id + decision_id + dimension_id` 去重。同一次决定的后续效果不重复记成新选择。
2. 检查维度 ID、行为标签、事件版本、可行替代方案和锁定原因。字段不足则标为 `insufficient`，不能补造。
3. 将 `eligible + direct_contextual` 纳入明确行为集合；将 `mixed_motive` 和约束记录分开保留。一个决定可支持少数已声明维度，但每个维度最多贡献一次。
4. 按“维度 → 人生阶段 → 目标关系类别 → 压力类别”分组；其他情境标签保留供筛选。禁止直接把极端生存压力下的选择与资源充足时相加，宣称是统一倾向。
5. 每组报告有效机会数、各行为分类次数、证据 ID、相近情境下的行为反例和局限。一次合格机会在组内只能落入一个主要行为分类；复合策略使用预设的 `combined_strategy`，不得重复计数。
6. 机会少时照实报告“仅观察到一次”。不同子情境机会数量不等时不比较高低；相关剧情连续多次提问应标记同一 `episode_id`，同时报告独立剧情数，避免把同一处境当作多次独立验证。
7. 首版不计算维度总分、加权人格分、百分位、人格类型或概率。也不设未经验证的“达到五次就稳定”阈值。

建议聚合输出：

```json
{
  "dimension_id": "care",
  "context": {"life_stage": "young_adult", "target": "neighbor", "pressure": "low"},
  "eligible_opportunities": 3,
  "independent_episodes": 3,
  "behavior_counts": {"provide_practical_support": 2, "decline_support": 1},
  "evidence_ids": ["ev_01", "ev_02", "ev_03"],
  "mixed_motive_evidence_ids": [],
  "excluded_evidence_ids": ["ev_04"],
  "limitations": ["尚未观察陌生人情境", "有一次选项受资源限制，已排除"]
}
```

安全表述：“成年早期、资源压力较低时，你在三次能够选择的邻里求助中，两次提供了实际帮助，一次拒绝。”

不支持的表述：“你的同情心为 87 分”“你天生自私”“你在现实中一定会帮助陌生人”。

## 7. NPC、玩家角色与现实玩家

- **NPC 模拟参数**：为驱动 NPC 决策配置的偏好和目标，属于游戏内部的行为模型，不是测量结论。
- **NPC 可观察画像**：玩家实际见到的 NPC 行为和关系经历。NPC 私下行动、隐藏目标与玩家未知事实不能提前进入可见报告。
- **玩家角色画像**：根据本局决策形成，受时代、角色处境、信息和游戏机制影响。它是本版本默认报告对象。
- **现实玩家人格**：不能由前面三者自动推导。玩家可能在扮演他人、测试选项、追求结局或读档尝试。

NPC 行为同样记录执行时的机会和约束，但不要把预设 NPC 参数经由其行为重新“测出来”当作模型有效性证明。玩家改变了 NPC 的资源或处境，也不等于改变了 NPC 的稳定人格。

读档和多周目分别保存。若提供跨局摘要，应明确每局的角色身份和玩法差异，不能直接合并为真人人格档案。

## 8. 人物志与画像报告约束

推荐报告顺序：

1. **人生事实**：家庭、职业、重要关系、转折与死亡；由已发生事实和状态日志生成。
2. **可观察的选择模式**：明确情境、行为次数与证据引用。
3. **取舍与变化**：不同阶段、压力或对象下如何改变；不把时间上的先后直接写成因果。
4. **反例与空白**：哪些选择不同，哪些方面没有观察机会。

每个事实性句子必须可追溯到事件或状态记录；每个画像判断必须可追溯到有效证据集合。允许文学化组织语言，不能杜撰对白、动机、亲密关系、心理疾病或未发生的事件。直接引语只来自真实保存的对话。

生成前由规则代码汇总计数与有效引用，生成后校验引用存在且属于当前角色、当前周目。模型不得修改聚合数值，不得将 NPC 的事件错归给玩家。无法通过校验时，回退到模板式报告。

## 9. 验证路线

### 第一阶段：内容和规则验证

- 为每个事件审核可行方案、维度关联、锁定原因、负担与可能的替代动机。
- 用成对情境检查归因：金钱充足/不足、家人/陌生人、公开/私下、可信/不可信求助渠道。
- 用回归样例验证：锁定不计拒绝、同一决定不重复计数、缺失数据不补猜、反例不被丢弃、NPC 与玩家日志不串用。
- 检查是否存在机械收益显著占优的“标准答案”；这类事件可以用于玩法，但不能直接用来区分价值偏好。

### 第二阶段：玩家可理解性与观察一致性

- 让玩家解释选项和选择原因，确认设计者预期与实际理解是否相符。
- 让不同内容审核者独立标注证据，检查分歧并修订定义。
- 检查同一维度是否只在某一身份、年龄或财富条件下出现；缺少机会应显示空白，不能补成中等倾向。

### 第三阶段：若以后要分析现实玩家

另行设计研究，检查跨情境、跨时间表现，以及与适当、经过验证且获准使用的量表之间的关系；检验角色扮演、数值优化、文化和可访问性因素。未经这一步，不升级为心理测量产品，也不沿用正式量表的名称暗示效度。

## 10. 参考依据与使用边界

- [Soto 与 John：BFI-2 原始研究](https://pubmed.ncbi.nlm.nih.gov/27055049/)：研究采用五个宽领域与十五个侧面的层级结构。本设计借鉴分层思路，没有实施 BFI-2 量表或其评分。
- [Lee 与 Ashton：HEXACO 维度说明](https://hexaco.org/scaledescriptions)：提供人格领域及侧面的定义，可帮助区分诚实、公平、人际行为等概念。本设计不复制其问卷题项。
- [Schwartz：基本人类价值观理论综述](https://scholarworks.gvsu.edu/orpc/vol2/iss1/11/)：讨论价值目标及其冲突、兼容关系，并区分价值与特质。本设计据此将价值目标与行为倾向分开。

这些来源支持概念区分，**不构成这八个游戏维度或从游戏决策推断人格已经有效的证据**。

## 11. 当前规则原型的适配与实现边界

本节对应 `prototype/engine.py` 的 `choose()`、`observations()` 以及 `content/events.json`。机器可读的标签映射另列于维度 JSON 的 `prototype_adapter`，不改变事件原始标签。

### 11.1 当前真正保存和输出了什么

`choose()` 将决策上下文保存在日志条目的 `payload` 中。`observations()` 只从具有至少两个实际可行选项的决策中提取简化行；**输出行是候选行为观察，不是已经满足第 4 节全部条件的有效人格证据**。

| 当前字段 | 所在位置 | 含义和适配限制 |
| --- | --- | --- |
| `dimension_id`、`behavior` | `payload.observations[]` 和简化行 | 事件作者预先写入的观察标签；保留原始标签，不把它当作引擎证明的动机 |
| `strength` | `payload.observations[]` 和简化行 | 当前仅 `limited` 或 `ambiguous`；均不自动映射为目标规范的 `direct_contextual` |
| `opportunity` | `payload` | 所有实际可行选项数是否至少为二；是机械门槛，不是维度相关性、信息充分或可承受性的证明 |
| `options` | `payload` | 所有展示选项的可行状态及 `locked_reason`；分析限制时应回到此处读取 |
| `locked_options` | 简化行 | 仅保存锁定选项 ID；原因需回查原始 `payload.options` |
| `context_tags` | `payload` 和简化行 | 模板的静态标签，不一定是状态动态判定；例如 `financial_pressure` 不代表已计算出统一压力等级 |
| `age`、`bindings`、`player_knowledge`、`presented_facts` | `payload` | 可回看的年龄、关系绑定和信息背景；不等于已经完成行为含义审核 |
| `resources_before` | `payload` 和简化行 | 决策前现金、精力、健康、压力及住处预算；属于情境，不是人格分数 |
| `cash_cost` | `payload` 和简化行 | 本原型选择效果中，从玩家转出的常量现金之和；没有涵盖时间、精力、风险或未来损失，也未承诺覆盖动态金额表达式 |
| `cash_cost_share` | `payload` | 上述现金成本占决策前现金的比例，分母为零时为 `null`；当前简化行未复制此字段 |
| `below_housing_reserve_after` | `payload` | 结算后现金是否低于住处预算目标；它不是已经失去住处或必然无法生存的判断 |
| `evidence_id` | 简化行 | 当前形如 `decision-3`，指向一次决策；一条决策的多个维度可共享此 ID，单行引用应连同维度和当前运行标识使用 |

`observations()` 当前不返回 `opportunity`、`cash_cost_share` 或 `below_housing_reserve_after`。如果报告需要这些信息，应依照 `evidence_id` 中的日志序号回查对应决策，不可假设简化行已经包含它们。当前也没有独立的持久化 `run_id` 或事件实例 ID，跨周目合并前需要外层提供运行标识。

### 11.2 行为标签对照

下表的通用类别只用于理解和后续人工审核。**当前原型保留原始行为字符串，不自动按映射合并次数，不把具体事件语义抹平成稳定人格。**

| 当前维度 | 原型 `behavior` | 通用类别候选 | 必须保留的语义 |
| --- | --- | --- | --- |
| `care` | `material_support` | `provide_practical_support` | 向朋友借出全额款项；属于有偿还约定的借款，不是捐赠 |
| `care` | `partial_material_support` | `provide_practical_support` | 部分借款；保留金额、占比和预算约束，不能与全额借款简单按强弱排序 |
| `care` | `practical_support_attempt` | `offer_alternative_support` | 付出精力尝试找办法；没有证明问题已解决，也没有完成通用时间资源模拟 |
| `care` | `declined_this_request` | `decline_support` | 只拒绝此次借钱请求；不等于拒绝一切帮助，尤其须检查借款选项是否被锁定 |
| `risk_taking` | `accept_financial_exposure` | `accept_risk` | 接受这笔借款的资金占用和违约暴露；当前没有可信的还款概率或充分风险信息建模 |
| `risk_taking` | `limit_financial_exposure` | `mitigate_risk` | 相比全额方案减少出借金额；若全额不可行，不能证明角色主动选择了降低风险 |
| `conflict_style` | `negotiated_extension` | `compromise` | 代码只延长到期时间，未模拟双方协商过程；最多表述为“同意延长期限”，不表述双方达成新共识 |
| `conflict_style` | `deferred_confrontation` | `avoid_engagement` | 暂停当前催促并保留债权；不证明长期回避冲突，也不证明放弃债权 |

原型中的这些选择并没有覆盖八个工作维度。没有事件观察的维度应显示“尚未观察”，不补成平均水平或推断其高低。

### 11.3 首版采用的保守输出规则

1. 展示原始行为条目、对应事件、静态情境标签和资源背景；所有条目明确保留 `limited` 或 `ambiguous`。
2. `opportunity = false` 时，原型不产生简化观察行；原始选择日志仍可作为人物志事实使用。
3. `opportunity = true` 只说明“机械上至少有两个方案能执行”。例如角色没钱时仍可“拒绝借钱”或“花精力找办法”，并不因此得到“愿意借钱/不愿借钱”的真实选择机会。
4. 两个选择都能执行，也不代表两者对每个维度都有区分力；不表示玩家知道全部风险，不排除生存约束、收益优化和扮演动机。
5. `limited` 解释为“作者标注的有限情境观察”；`ambiguous` 解释为“动机或含义尤其不明确”。两者都只是描述标签，不升级为已验证证据，也不换算分数或概率。
6. 当前不运行第 6 节的完整计数聚合，也不生成稳定人格结论。若暂时统计调试数量，标题须写“原始观察条目数”，不能写“有效人格观察次数”。
7. 住处预算只是预算目标，且原型尚未扣除真实租金；不得根据预算标志写出“你宁愿无家可归也帮助朋友”等未发生事实。

后续要实现完整目标，需要补充按维度的相关可行选项、动态情境与负担、明确证据审核状态、独立剧情标识和反例聚合。先补数据和规则，再开放画像总结，不由大模型替缺失字段猜答案。
