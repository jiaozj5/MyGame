# 人物画像评价体系 v0.6

## 定位

v0.6 评价的是**本局虚构角色在具体情境中的可观察行为**。它不是 MBTI、临床量表或现实玩家人格诊断，也不输出心理测量分数、百分位、人格类型或概率。

画像的基本单位是：

`本局运行 · 一次选择 · 一个观察维度`

事件作者先声明“这个选择观察什么行为”，引擎再把实际可执行的选项、资源、压力、关系和已知信息写入时间线。报告只从已经发生且可以回看的记录中归纳。

## 八个维度与子维度

八个维度继续保持稳定，详细定义位于 `content/personality-dimensions.json`。每个维度拆成三个工作子维度，便于事件覆盖和报告解释：

| 维度 | 子维度 |
|---|---|
| 探索与熟悉偏好 | 接近新事物、先获取信息、保留熟悉做法 |
| 目标坚持与调整 | 目标投入、方法调整、暂停与退出复评 |
| 社交发起方式 | 发起接触、社交选择、主动独处 |
| 关怀行为与对象范围 | 注意需求、支持方式、关怀边界 |
| 公平与承诺取舍 | 分配原则、承诺管理、利益冲突披露 |
| 冲突处理方式 | 主张边界、协商妥协、退出与调解 |
| 风险应对方式 | 接受风险、风险信息、降低风险 |
| 求助与自主应对 | 发起求助、先自主处理、信任与互惠 |

子维度是内容索引和解释标签，不是分数轴。一个选择可以同时观察多个维度，但必须由事件作者逐项标注。

## 证据资格

一条选择记录只有在以下条件满足时，才会进入“有效机会”：

1. 事件确实向角色展示了选择情境。
2. 至少有两个实际可执行选项。
3. 选择前的资源、关系和已知信息已经写入记录。
4. 选择没有被资源、身份、能力、时间或安全条件硬性决定。
5. 事件事先声明了相关维度和行为标签。

受限选择仍然保留在完整年表中，但不会被解释为自由偏好。尤其是“因为没钱无法帮助”不等于“选择了不帮助”。

## 报告字段

每个维度返回：

- `eligible_opportunities`：通过资格审查的相关机会数。
- `independent_episodes`：按 `episode_id` 去重后的独立剧情数。
- `behavior_counts`：具体行为标签的出现次数。
- `context_counts`：年龄阶段和事件情境标签下的行为记录数。
- `opportunity_context_counts`：相关机会在各情境标签下的数量。
- `facet_counts`：子维度标签的出现次数。
- `pressure_counts`、`relationship_counts`：事件作者声明的压力和关系范围分布。
- `information_counts`、`horizon_counts`：角色做决定时掌握的信息程度和时间跨度分布。
- `evidence_ids`、`counter_evidence_ids`：可以回看的人生记录。
- `evidence_level`：材料不足、单次观察、重复观察或跨剧情重复观察。
- `limitations`、`excluded_evidence_ids`：为何不能进一步归纳。

“跨剧情重复观察”只表示多个独立剧情中出现过相同的行为记录，不表示人格稳定性已经被心理测量验证。不同做法不会互相抵消，也不会被换算成善恶高低。

## 事件库覆盖

`content/personality-coverage.json` 是编辑用覆盖矩阵。它为每个维度列出童年/少年、成年转折、较高压力和晚年支持等情境，并引用实际存在且预标注该维度的事件。`game/content_check.py` 会检查：

- 八个维度是否齐全；
- 每个维度是否至少有四个事件入口；
- 引用的事件是否存在；
- 矩阵所列维度是否真的出现在事件选项的观察标注中。

事件资产增加了 `episode_group`、`assessment_context` 和观察项 `facet`。这些字段只描述内容设计者声明的情境，不改变选项的规则执行，也不从结果倒推动机。

## 已知边界

- 当前机会门槛仍是“总可执行选项至少两个”，尚未做到逐个子维度验证替代方案是否真正相关。
- 压力和关系分布依赖事件作者的元数据，不能替代完整的经济、信息和动机模型。
- 社交记录目前主要用于关系小传；只有带有正式 `observations` 的选择才进入八维画像。
- 画像不会将 NPC 私下属性、玩家未见事实或事件结果反推为玩家动机。
