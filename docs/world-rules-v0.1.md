# 世界规则规范 v0.1

状态：设计草案与本轮规则验证原型的共同约定。本文先定义完整系统的目标，再单独限定本轮实现范围。完整目标不代表本轮已经实现。

## 一、设计目标与世界边界

本游戏通过角色从出生到死亡的一系列选择，形成可追溯的人生经历，并依据实际选择及其处境生成角色人物志。世界应当允许意外与变化，同时保证已发生的事实、人物当前状态和后续事件相互一致。

### 1.1 初始社会背景

首个内容包设定在虚构的现代小城「河湾」。这是一个能够步行或短途通勤、熟人关系较多的小城，包含家庭住宅、出租房、学校、社区诊所、小型企业、商店和公共场所。现代通信、货币交换、普通就业和基础公共服务存在。

这个设定提供事件成立所需的社会条件，不映射任何现实城市或司法辖区。工时、医疗费用、借贷和继承等机制由游戏规则明确规定，不把现实中复杂且因地区而异的制度作为默认常识。

首版重点覆盖家庭、友谊、谋生、照护、日常健康和承诺。世界中的人口和地点可以逐步扩展，但进入当前人生叙事的具体人物必须具有稳定身份。内容不足时允许平淡的生活和时间推进，不强行制造事故。

### 1.2 权威来源

世界事实由状态存储和事实日志共同维护。叙事文本是事实的表达，不能自行新增已经成立的亲属关系、财产、死亡或历史。

大模型可以提议内容、组织措辞、概括历史；规则引擎决定一个事件能否发生，以及选择是否改变世界。预生成文本同样需要通过规则检查，不能因为已经写好而获得执行资格。

规则只能保证已明确编码的约束。物理、社会、情感和语言常识没有被全部形式化，本文不承诺任意生成内容都符合全部现实常识。

## 二、时间、年龄与人生推进

### 2.1 统一时钟

- 世界日 `day` 从 0 开始，使用非负整数。
- 角色出生日期 `birth_day` 使用同一坐标；已经出生的人可以具有负数出生日期。
- 年龄统一计算为 `floor((day - birth_day) / 365)`。这是每年固定 365 天的明确简化，不包含真实月份、闰年或出生时刻。
- 尚未出生的人不作为可行动角色；其出生应当通过具有前提的事件进入世界。
- 时间单向推进。修改历史属于显式的存档回退或迁移，不能由普通事件悄悄完成。

本轮演示从玩家 24 岁开始：玩家 `p` 的 `birth_day` 为 -8760，所以 `day=0` 时年龄是 24 岁。这不代表本轮已经实现出生到死亡的完整流程。

### 2.2 决策暂停与时间成本

玩家阅读事件、查看选项和思考期间，世界时间暂停。没有后台时钟让 NPC 在玩家阅读时突然变更状态。

每个会推进时间的行动必须声明耗时。选择提交和时间推进是受控操作；时间不能由生成文本中的“几天后”隐式改变。一次跨越多天的行动仍要处理途中到期的事件，不能直接跳过它们。

完整系统可以在婴幼儿期、稳定生活期使用较大的叙事跨度，在危机和重要关系事件中缩短跨度。但所有跨度都要停在下一项必须处理的计划、资源检查或叙事决策之前。

### 2.3 阶段是内容标签

完整内容规划可以使用幼年、儿童、青少年、成年和老年等阶段标签。阶段标签用于筛选相称的情境，不意味着到了某个年龄必然结婚、就业、生病或死亡。

具体年龄范围由内容包定义并版本化。事件依赖精确年龄时使用实际计算结果；不根据文案中的“年轻”“年迈”推导硬性资格。

## 三、资源、需求与个体差异

### 3.1 分层建模

完整系统应区分四类信息，避免把所有人的需求压成一种总分。

| 层次 | 含义与例子 | 设计要求 |
| --- | --- | --- |
| 可支配资源 | 金钱、可用时间、精力、物品 | 能够获得、消耗或转移；成本必须有明确来源 |
| 身体与心理状态 | 健康、压力、疾病、伤势 | 有边界和持续影响；不等同于人格好坏 |
| 需求是否满足 | 食物、休息、住所、安全、归属、自主、胜任与意义 | 可以由状态和事实推导，不要求全部做成独立数值条 |
| 稳定差异与生活条件 | 技能、价值倾向、身份、关系、机会、过往经历 | 改变可选行动和解释情境，不能随意作为消耗品 |

需求不足可以造成后续压力、健康损失或机会变化。作用周期、阈值和恢复规则必须明确，不能根据文本气氛临时扣分。

人格倾向不直接作为可花费的资源。角色没有足够金钱帮助别人，不能因此被判定为缺乏关怀。行为证据必须保留当时的资源、可用选项和限制。

### 3.2 原型的数值约定

- 金钱为非负整数单位，不使用小数。单位是虚构记账单位，不声明与人民币等现实货币的换算关系。
- 精力、健康、压力的有效区间为 0–100。精力与健康较高通常表示状况较好，压力较高表示负担较重。
- 更新后越界属于无效状态，应当拒绝本次变更。事件若需要“最多恢复到上限”，必须明确使用有上限的恢复语义，不能依赖偷偷截断数值掩盖错误。
- 金钱不能隐式为负。借款通过独立债务记录和对应的资金变化表示。
- 原型不通过精力为零自动推导昏迷，也不通过压力高自动推导精神疾病。完整系统中的致死、失能和恢复机制，需要单独的明确规则。
- 原型没有日常生存自动扣减，也不因健康归零自动判定死亡。推进日期不会自动扣房租、降低健康或增加压力；这些后果必须来自已实现的明确事件。

这些范围用于验证边界与成本，不是已经平衡完成的游戏数值。

### 3.3 硬门槛与软条件

**硬门槛**决定行动是否成立。不满足时选项不可执行，并显示具体原因，例如：

- 支付 20 单位但只有 12 单位金钱。
- 要求朋友本人回应，但朋友已经去世。
- 行动要即时消耗 8 点精力，但当前只有 3 点。
- 要向债权人还款，但不存在对应的未清偿债务。
- 事件需要共同在场，但人物无法在规则允许的时间到达。

**软条件**影响难度、概率、收益或代价。不满足理想状态时仍可尝试，例如关系较疏远导致请求帮助的成功率较低，压力较高增加谈话失控的可能。

同一属性可以在不同事件中承担不同职责，但每个选项必须说明其具体用法。“建议精力至少 40”不能被实现成未声明的硬锁定；“支付精力 10”也不能被当作可选建议。

不采用“先允许提交，再悄悄扣成负数”的透支方式。如果未来加入透支，应将它定义为独立选项，明确健康或压力代价。软条件可以允许失败，不能允许违反生死、资源和物理约束。

## 四、NPC：历史、状态、知识与计划

### 4.1 稳定身份

每位进入事实日志的 NPC 都有稳定 ID。姓名、外貌或职业改变不生成一个替代身份；重名也不表示同一个人。

本轮演示人物固定为：`p` 是玩家，`f` 是朋友，`m` 是母亲。展示名称可以修改，规则和历史引用始终使用稳定身份。

### 4.2 四种信息必须区分

| 信息 | 例子 | 变化规则 |
| --- | --- | --- |
| 历史事实 | 曾向玩家借钱、曾参加一场谈话 | 已提交事实不覆盖；后来可以新增解释或纠错事实 |
| 客观状态 | 存活、位置、年龄、健康、持有物与身份 | 通过规则允许的行动和时间演化更新 |
| 个人知识与信念 | 知道一笔债务、误以为某人失约 | 与客观事实分开；记录来源与获得时间 |
| 未来计划 | 三天后归还借款、明天去诊所 | 带前提和状态；可以被取消、失败或改期 |

预生成内容可以设定 NPC 的初始经历和倾向，不能把完整未来命运写成不可变事实。玩家改变 NPC 的资源、关系或环境后，相关计划必须重新评估。

### 4.3 知识边界

一个秘密客观发生，不代表所有 NPC 自动知道。NPC 的决定只能使用其拥有的信息；误会应当是显式信念，不能让客观数据库也变成错误版本。

遗书、留言和回忆的内容受形成时刻约束。生前写下的信不能准确提及写信者当时不可能知道的后来事实，除非内容被明确标记为猜测。

这是完整目标。本轮只保存与事件有关的事实和证据，不实现完整信念传播、秘密系统或基于知识的 NPC 决策。

## 五、关系、死亡与遗留事务

### 5.1 关系的方向

朋友关系是双方共同认可的一条关系，新增和移除时保持双方一致。家人关系应当区分具体角色：母亲与子女是互为反向的关系角色，不是把“母亲”原样写入双方。

信任、亲近、依赖和怨恨可以是单向数值。A 信任 B 不意味着 B 同样信任 A；不能把情感的非对称性当作数据错误。

本轮仅验证朋友、家人关系及其一致性，以朋友和家人标签表示共有关系。母亲身份来自演示设定，本轮不实现完整亲属角色推导、关系数值向量、婚姻制度或家谱。

### 5.2 死亡是明确且不可逆的状态转换

在本内容包中，角色从存活转为死亡后，不允许普通事件令其恢复存活。闪回、梦境、遗留信件和他人回忆必须明确标识，不能作为当下本人正在行动的证据。

死亡记录保留发生日期和原因；未知原因可以记录为未知，不能由后续文案擅自补造。完整系统应明确哪些健康条件导致死亡，本轮用显式 NPC 死亡来验证一致性，不实现完整寿命或自动死亡模型。

死亡不会抹除这个人：

- 历史事实、亲属身份和已经发生的影响继续存在。
- 死者不能继续产生新的主动行动。
- 需要死者本人到场或答复的计划会失效；死亡时可以主动标记取消，到期时仍需重新校验。
- 已经发出的物品、合法存在的留言或其他人承担的事务，可以在满足各自条件时继续发生。

### 5.3 债务与遗留事项

债务至少表达债权人、债务人、整数本金及清偿状态。借款和还款必须同时改变资金与债务，不能只改其中一侧。还款不得超过尚未清偿的债务，也不能出现负债务。

本轮 `amount` 是创建债务时的固定本金，清偿后仍保留原值以供审计；`status` 表示处理状态。本轮只支持整笔清偿：`outstanding` 的未偿金额等于本金，`repaid` 的未偿金额为 0，`deceased_pending` 保留未偿本金等待后续处理。不能把已清偿记录中的 `amount` 再计入未偿总额。部分清偿及独立余额字段留待后续实现。

死亡不自动删除债务，也不自动把债务转给家属。完整系统可以加入遗产结算，但必须以明确制度和独立事件处理。

本轮没有遗产制度：债权人或债务人死亡后，未清偿债务保留本金，转为 `deceased_pending`（相关当事人已故、后续处理待定）；要求死者本人参与的计划取消。这个状态不表示债务被免除，也不表示已发生法律上的继承。不会通过新生成一位家属或自动扣取家属金钱完成结算。

### 5.4 一致性示例

朋友承诺三天后归还借款。次日朋友去世。三天后不能出现“朋友登门还钱”。到期计划应因参与者已故而被取消或记录为未能执行，债务仍然保留。

如果内容另行设置“收到朋友生前已经寄出的信”，则需要证明信件确实在生前形成并发出，或通过另一个经过验证的遗留物发现规则建立事实。不能直接把原来需要本人参与的事件换一句文案后执行。

## 六、物理约束与事件资格

### 6.1 完整系统的硬约束

- 时间顺序：原因早于结果，人物不能在出生前行动。
- 生死状态：死者不执行新的主动行为。
- 位置与移动：需要在场的事件满足地点条件和移动耗时，远程事件明确通信方式。
- 资源与对象：花费来自真实余额；物品转移不凭空复制；工作报酬等新增资金有规则规定的来源。
- 身份与关系：要求母亲、同事或债权人的角色，必须由符合关系和身份条件的人物承担。
- 事件资格：时代、年龄、经历、冷却和互斥条件在执行时成立。

这些约束不意味着必须模拟全部粒子、疾病和经济流动。模型粒度应服务于玩家能够观察并作出选择的后果。

本轮不实现位置图、交通、物品所有权、职业资格或完整社会经济守恒。事件文案必须限制在已经支持的场景范围，不能据此宣称这些约束已经通过程序验证。

### 6.2 内容不足时的行为

事件筛选没有结果时，可以休息、维持日常或推进到下一项需要处理的事务。系统可以说明当前没有新的重要事件，不能为了填充事件而忽略资格条件。

生成候选事件验证失败时不修改世界。使用经过审核的备用内容，或把错误留在开发日志中，等待内容修复。

## 七、事务、计划与确定性回放

### 7.1 选择事务

一次选择按照以下顺序处理：读取当前状态、检查事件资格、检查选项硬门槛、计算拟议结果、验证所有结果、整体提交、记录事实与行为证据。

扣款、资源变化、关系变化、债务变化与相关计划创建应作为同一事务。任何一步不成立，整个选择都不能留下部分修改。

事件展示时的资格只是快照。提交前仍检查当前状态，避免旧事件对象被重复使用或在世界已经变化后提交。相同选择不能因重复点击而执行两次。

被拒绝的操作可以进入独立诊断记录，但不进入“玩家实际做过什么”的人物志证据。

### 7.2 延迟事件

计划至少具有唯一身份、创建顺序、到期日、参与者、执行前提和处理状态。待处理、已执行、已取消或无法执行等状态必须能区分，不能用删除记录掩盖失败原因。

到期计划按“到期日、计划在列表中的插入顺序”稳定处理：到期日相同则保留已有插入顺序，不按任务 ID 的字典顺序排序。每条执行前重新检查前提，较早计划产生的状态变化对后面的计划立即生效。计划延期更新到期日，但不虚构新的创建历史。

计划到期可能意味着一个新的选择事件可以出现，也可能意味着一个明确的系统后果需要执行。这两种语义必须分开：玩家尚未选择时，不能把一个可选事件的后果当作已经发生。

本轮延迟事件安排在未来日期，不使用同一日无限创建并立即执行新计划的机制。推进日期只推进日时钟并激活到期计划，不替玩家选择或自动结算借还款；参与条件失效的计划应取消或保持不可执行，并留下原因。到期后的事件提交仍需检查资格与成本，且只能结算一次。跨日推进不能漏掉途中已经到期的计划。

未来如果需要同日多时段、紧急中断或特殊优先级，必须明确排序规则并升级版本，不能让大模型临时决定谁先发生。

### 7.3 事实日志与行为证据

日志记录实际发生的日期、参与者、事件和选项版本、提交前的必要条件、实际结果以及关联计划。涉及随机性时保留实际抽样结果；不能回放时重新抽签。

行为证据应能回答：玩家当时有哪些选项、哪些被硬门槛挡住、选择承担了什么代价、是否存在已知风险。结果不佳不直接等价于动机不好；计划未实现也不等价于玩家没有做出承诺。

人物志中的事实判断引用已提交日志。推断必须与事实区分，并保留不确定性。没有发生的候选事件不得进入角色传记。

### 7.4 回放、快照与版本

完整系统保存规则版本、内容版本、事实日志和定期快照。回放应用已经记录的结果，不调用大模型重写历史，也不使用新版规则重新解释旧选择的成本。

旧存档升级需要显式迁移；迁移不得伪装成玩家曾经做出的决定。本轮验证事实日志与证据可追溯，完整存档迁移、资产发布和跨版本回放属于后续工程。

## 八、时代扩展与内容增长

时代扩展应通过相互兼容的内容包和规则版本进行。每个包声明可用身份、技术、地点类型、服务、制度、计量单位和事件适用条件。

不能仅替换现代事件中的名词，把“发消息”“去医院”“办理继承”直接放入任何时代。通信速度、交通、医疗能力和家庭制度改变时，事件的前提、成本与后果也必须改变。

同一人物在一个存档中使用统一的时间坐标和身份记录。跨时代跨度若超出已支持范围，应当明确结束或等待新的内容支持，不能无声明地加载一套互相矛盾的制度。

内容规模优先来自经过校验的模板、人物绑定和情境组合。事件库可以逐步增大，但“覆盖所有人的全部可能人生”不作为可验证的版本验收条件。

## 九、本轮规则验证原型的明确范围

**本轮规则验证原型只验证日时钟、金钱／精力／健康／压力、NPC 存活、朋友／家人关系、债务、延迟事件、事实日志与证据；没有完整人生模拟、UI 或实时 LLM。**

它从小城中的一位 24 岁玩家及朋友、母亲开始，用少量可执行事件检查规则，而不是向玩家提供一局完整人生。2D 像素风属于后续界面目标，本轮没有美术或界面验收。

本轮 `advance` 只推进日期并激活到期计划；NPC 死亡由显式系统命令 `mark_dead` 设置。演示中的 500 单位住房备用金属于 `housing_reserve` 目标信息，用来说明选择时的生活处境；它没有到期日期，也没有自动房租扣款。

| 项目 | 本轮检查范围 | 尚未实现的完整目标 |
| --- | --- | --- |
| 时间 | 整数日、明确耗时、年龄简化、决策暂停、到期计划激活 | 多阶段人生节奏、长期自动生活模拟 |
| 生存 | 四项数值边界、成本资格与事务结果 | 饮食住所需求、疾病、自然衰老与完整死亡机制 |
| NPC | 稳定身份、存活检查、关系与事件资格 | 自主行动、完整知识信念、细粒度个人时间线 |
| 社会 | 朋友／家人关系、借款与还款 | 复杂社会制度、遗产、职业与人口经济 |
| 叙事 | 实际事实日志及可追溯的行为证据 | 人物志生成、完整人格量表或现实人格测评有效性 |
| 内容运行 | 少量明确事件及延迟事件的合法执行 | 大规模资产生成、审核发布、实时模型生成 |
| 持续运行 | 当前规则下可观察的结果与失败原因 | 完整存档迁移、跨版本回放与规模性能保证 |

### 9.1 本轮应覆盖的关键检查

1. 玩家付不起选项声明的即时成本时，操作被拒绝，资源、债务、计划和行为证据均不发生部分改变。
2. 可以尝试的软条件不会被误当成硬门槛；尝试结果仍须满足硬约束。
3. 借还款的双方金钱、固定本金与清偿状态保持一致；整笔清偿后本金记录仍在，但未偿金额为 0；重复提交不能重复结算。
4. 朋友关系和家人关系的双方表示一致，演示中玩家、朋友和母亲的身份引用保持稳定。
5. NPC 去世后，需要本人主动参与的延迟事件不能执行；历史关系和未清债务仍保留。
6. 跨多日推进按稳定顺序激活到期事件，不漏算、不重复，不替玩家自动作出选择，也不在玩家阅读时偷偷推进。
7. 已执行选择能够追溯其事实与行为证据；被阻止的选项和未发生的候选事件不冒充经历。

以上是验证目标清单，是否已经通过应由对应的实际运行结果说明，不能仅凭本规范的存在宣称通过。
